# MyBlog 学习笔记

> 第一版开发完成后的复盘。前半部分是"怎么做的、为什么这么做"，最后两节是"踩过的坑"和"你问过的问题"。
> 阅读顺序建议：先看第一节建立全局，再挑自己还没想通的小节读。

---

## 一、这个项目由什么组成

### 一次请求的完整链路

```
浏览器
  │  fetch('/api/v1/articles')
  ▼
Vite 开发服务器（5173）
  │  /api 开头的请求转发到 3000 —— 浏览器以为同源，所以不用配 CORS
  ▼
Express（3000）
  │  helmet → json 解析 → 路由 → requireAuth（按需）→ service → repository
  ▼
MySQL（3306）
```

**为什么要走 Vite 代理**：前端和后端是两个端口，浏览器默认禁止跨源请求。代理让浏览器"以为"自己在请求 5173，跨域问题就消失了。生产环境通常由 Nginx 做同样的事。

### 目录结构

```
client/src/
  pages/        页面（每个路由一个）
  components/   可复用组件（列表行、目录、分页…）
  features/     带状态的业务逻辑（auth、article、admin 的接口封装）
  lib/          与页面无关的工具（请求、格式化、阅读进度、目录解析）
server/src/
  modules/      按业务切分：user / session / article / category / admin
  middleware/   auth、错误出口、限流
  lib/          错误类、JWT、校验、相似度算法
  sql/          建表与种子数据
docs/           接口文档、进度、本笔记
```

**分层原则**：`routes` 只解析 HTTP，`service` 写业务规则，`repository` 只写 SQL。好处是加功能时基本只新增目录，不改别人。

## 三、关键设计决策

### 1. 密码只存哈希，登录时故意"慢"一点

```ts
bcrypt.hash(password, 10)   // 约 100ms
```

密码永远不加密后存（加密可逆），而是**哈希**（不可逆）。成本因子 10 让每次校验都要算 100ms——攻击者试一亿个密码的时间成本被放大到不可行。

还有一个小细节：用户不存在时也拿一个固定的假哈希比对一次。否则"用户不存在"会比"密码错误"快 100ms，攻击者靠计时就能判断哪些邮箱注册过。

### 2. JWT 里只放 id 和版本号，且每次请求都查库

```ts
payload = { sub: String(userId), ver: tokenVersion }
```

只验签名是不够的：签名有效不代表账号还能用。所以中间件每次都查一次库，拿到当前的 `status`、`role`、`token_version` 再判断。

代价是每个受保护请求多一次主键查询——博客量级完全无感，但换来了"封号立刻生效"。

### 3. 退出登录 = 版本号 +1

JWT 是无状态的，服务端不记账。如果只在前端删掉 token，被抄走的旧票仍然有效到过期。

`users.token_version` 解决了这个问题：登录时把版本号写进票里，退出时 `+1`，之后所有旧票的版本都对不上，立刻失效。副作用是"退出会踢掉该用户所有设备"。

### 4. 错误只允许一种形状

```json
{ "error": { "code": "EMAIL_TAKEN", "message": "...", "details": [] } }
```

前端只需要写一处解析逻辑。状态码分工：400 参数、401 未认证、403 无权限、404 不存在、409 冲突、413 载荷过大、429 太频繁。

### 5. 接口按资源命名，版本号放路径里

`POST /api/v1/sessions`（登录 = 创建会话）、`DELETE /api/v1/sessions/current`（退出 = 删除会话）。路径里不出现动词。

版本号的意义：将来接口不兼容地改动时，可以让 `/v1` 和 `/v2` 并存，老客户端不会立刻坏掉。

### 6. 分类删除交给数据库，再把报错翻译成人话

外键设 `ON DELETE RESTRICT`，分类下有文章时数据库直接拒绝。应用层再先查一次数量，返回：

> 该分类下还有 8 篇文章，先把它们移到别的分类再删除

**为什么两层**：只靠代码判断，任何一次手工 SQL 或数据修复脚本都能绕过；只靠数据库，用户只会看到 `Cannot delete or update a parent row`。

### 7. 标签多对多：一条语句搞定"新建或取已有"

```sql
INSERT INTO tags (name) VALUES (?)
ON DUPLICATE KEY UPDATE id = LAST_INSERT_ID(id)
```

名字已存在时，MySQL 会把它的 id 放进 `insertId`，所以"不存在就新建、存在就拿旧 id"用一条语句完成。

### 8. 浏览量 +1 必须带上 `updated_at = updated_at`

`articles.updated_at` 有 `ON UPDATE CURRENT_TIMESTAMP`。如果只写 `SET view_count = view_count + 1`，**每有人看一次文章，"更新于"的时间都会被刷新**。所以要显式把它赋成自己。

### 9. 草稿对外返回 404，而不是 403

403 等于告诉探测者"这篇文章存在，只是你看不到"，泄露了草稿的存在。404 什么都不说。

### 10. 标签检索：相似度在 Node 里算，排序在 SQL 里做

MySQL 没有字符串相似度函数，所以：

1. 取出全部标签（几十个，很便宜）；
2. 用"包含关系 + 编辑距离"算每个标签和目标标签的相似度；
3. 把 `(tag_id, weight)` 拼成一张临时表传进 SQL；
4. 每篇文章取命中标签的**最高**权重作为得分，按得分倒序。

用 `MAX` 而不是求和：分数始终在 0~1，排序结果可解释（完全相同的永远高于相近的）。

### 11. 列表刷新依赖"原始查询串"，而不是解析后的值

这是踩过的最隐蔽的一个坑。地址从 `/tech` 变成 `/tech?page=1` 时，`page` 解析出来一直是 1——如果 effect 依赖 `page`，它认为什么都没变，不重新请求；而点击时已经把列表清空了，页面就永远停在"加载中"。

**地址是唯一的事实来源**，依赖 `searchParams.toString()` 才可靠。

### 12. 目录点击不生成锚点 id，按下标跳转

中文标题重复很常见（两篇都有"小结"），用文字生成 id 会撞车。改成"目录第 N 项 → 正文第 N 个 h2/h3"，既不会撞，也不用改 Markdown 渲染器。

### 13. 两种版面：技术文章宽版心、日常思考窄版心

v0 稿里技术文章是双栏，实现时改成了宽版心（44em）。原因：**双栏是印刷的解法，不是屏幕的**——每读完一列眼睛要横跨整个页面，长文会累。

### 14. 图片：不发 Referer + 失败兜底

很多图床有防盗链，看到陌生来源就拒绝。给图片加 `referrerPolicy="no-referrer"` 往往能正常取图。同时监听 `onError`，加载失败就回落到用户名首字母，不留破图图标。

## 四、开发者提问整理

> 这部分按"你当时问的问题"整理，答案做了压缩，方便以后回看。

**1. 为什么目录叫 `client/server` 而不是 `frontend/backend`？**
没有技术差别，纯命名习惯。`client/server` 描述的是"谁发请求、谁应答"，和架构图对得上；`backend` 有时会被理解成"包含数据库"，容易含糊。

**2. 密码要"加密"存吗？**
不能。加密可逆，泄露就能还原。要用**哈希**（单向），只存结果，永远不存明文。

**3. `token_version` 是干什么的？**
让"退出登录"在服务端真正生效。JWT 本身无状态，不加这个字段的话，退出只是前端删了 token，被抄走的票还能用满 7 天。

**4. npm 安装时报 `allow-scripts` 警告是什么？**
新版 npm 默认拦截第三方包的安装脚本（防止恶意包在安装时执行代码）。那次被拦的是 esbuild 的 postinstall，它只是下载平台二进制，而我们用的版本已经把二进制作为可选依赖装好了，所以不用处理。

**5. 那串安装命令为什么那么长？**
`npm install -D` 后面每个空格隔开的词都是一个包名，可以一次装多个。前端需要构建工具链（Vite、TS、类型包、Tailwind、ESLint 及插件），所以长；后端只需要 TS 检查和运行器，所以短。

**6. 项目里有没有没用的文件？**
没有死文件。只有两类"临时产物"：`dist/`（构建输出，已忽略）、写作台里曾经的健康检查按钮（M1 后拆掉，但 `/api/health` 接口保留用于部署探活）。

**7. 有了类型和标签，分类是不是重复了？**
维度不同：**类型**是体裁（固定两种）、**分类**是栏目（管理员定义、单值）、**标签**是话题（作者自由、多值）。分类解决的是"谁有权定义词表"——多用户场景下，只有管理员能加分类，导航骨架才不会被 100 个作者造出 100 种写法。个人博客可以不要分类，多用户平台需要。

**8. 点标签能不能搜到相似标签的文章？**
能，而且按相关度排序：完全相同 1.0，包含关系 0.5~0.9，拼写接近按比例打折，同分按时间倒序。

**9. 为什么刷新详情页浏览量 +2？**
开发模式下 React 的 `StrictMode` 会故意把 effect 执行两次（挂载→卸载→再挂载），于是详情请求发了两次。修法是缓存请求本身，第二次复用同一个 promise。

**10. 封面必须放文章开头吗？**
不必。填了 `cover_url` 才显示在标题下方；想把封面放进正文，直接不填这个字段，用 Markdown 图片，位置由作者决定。

**11. 文章目录作者能自选吗？**
能。写作台勾选后，详情页在正文前渲染目录；目录由正文里的 `##` / `###` 自动生成，作者不用手写。

**12. 邮箱要求"真实存在"要怎么做？**
只校验格式做不到验证真伪，唯一办法是发验证邮件。这属于邮箱验证，和密码找回是同一套东西，第一版按 PRD 排除，放到第二版一起做。

**13. 上云要清空数据吗？管理员密码要改吗？**
上云是"把数据从本地库搬到云库"，可以导出再导入，不必清空。要改的不是"本地密码"，而是"生产库从第一天起就用强密码"；如果导入时把本地用户一起带过去，导入后要立刻重设管理员密码。

**14. 为什么不能直接用 root 连库？**
root 能删所有库、建账号、读一切。业务账号只授权一个库的四件事，即使密码泄漏，损失也被限制在一个库里。

**15. 生产 `.env`、换 `JWT_SECRET`、开 SSL 是什么意思？**
云服务器读的是它自己那份配置文件（库地址、密码、密钥都不同）。`JWT_SECRET` 是签发登录票的签名密钥，本地那串带上去等于让人能伪造管理员登录。SSL 是因为云端连接要穿过公网，不加密的话密码和查询内容全是明文。

## 五、踩过的坑

| 现象 | 根因 | 修法 |
|---|---|---|
| 数据库连接 1045 | `.env` 里的应用密码与账号实际密码不一致（与 root 密码无关） | 用 `ALTER USER ... IDENTIFIED BY` 重设后同步 `.env` |
| 分类下拉顺序像随机 | `utf8mb4_0900_ai_ci` 对中文按码点排序 | 改成按 id（创建顺序）排 |
| 刷新详情页浏览量 +2 | StrictMode 双执行 effect | 请求级缓存，同 id 只发一次 |
| 别人能打开我的编辑页 | 编辑页复用了"公开阅读"接口，没校验归属 | 加载后比较 author.id，不是本人就渲染无权限页 |
| 点分类按钮卡"加载中" | effect 依赖解析后的值，地址变了但值没变 | 依赖原始查询串 |
| 头像不显示 | 图床防盗链，浏览器带了 Referer | `referrerPolicy="no-referrer"` + 失败兜底 |
| 接口全部 404（两次） | 端口上跑着上一轮遗留的旧进程 | 启动测试服务前先确认端口释放 |
| 搜索中文查不到 | PowerShell 把中文参数按本地编码传给 curl | 用 `[uri]::EscapeDataString` 编码后再请求 |
| 搜 "100%" 匹配到一切 | `LIKE` 里 `%` 是通配符 | 转义 `%` `_` `\` |
| 编辑文章时标签被清空 | PATCH 里"没传"和"传空数组"没区分 | 不传就不动，传 `[]` 才清空 |

## 六、如果重来，我会改什么

1. **时间一开始就用 UTC 存**。现在按服务器本地时间写 `DATETIME`，部署到 UTC 机器会整体差 8 小时，这是明确的部署前待办。
2. **数据库迁移用版本表**，而不是手工按顺序执行 `001/002/003`。文件一多，"这台机器跑到第几个了"就会变成谜。
3. **更早引入端到端测试**。这一版所有页面验证都靠人工点击，接口层有脚本但界面层没有。Playwright 能把这 20 项点击变成可重复执行的东西。
4. **详情页按需加载**。`react-markdown` 让首包到了 463KB，列表页其实用不到它。
